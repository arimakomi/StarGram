# برنامه پیاده‌سازی: سیستم جامع API مدیریت، اصلاح لوگوها، مستندات GitHub Pages و شخصی‌سازی پیشرفته

طرح جامع برای ارتقای استارلی چت شامل ۵ محور اصلی: حذف کادر مربعی لوگو در صفحه اصلی و بارگذاری با اندازه بزرگ و تراز دقیق، پیاده‌سازی REST API قدرتمند و امن برای ساخت اپلیکیشن‌های جانبی و بات‌ها محافظت‌شده با توکن‌های طولانی، راه‌اندازی مستندات تعاملی در GitHub Pages و پوشه Help، پاکسازی فایل‌های اضافه، و افزودن سیستم شخصی‌سازی هویت بصری پیام‌رسان در پنل ادمین.

> [!IMPORTANT]
> تصمیمات کلیدی تأییدشده توسط شما در فاز شفاف‌سازی:
> 1. **سطح دسترسی API**: دسترسی همه‌جانبه شامل احراز هویت، ارسال و دریافت پیام‌ها، مدیریت چت‌ها/کانال‌ها/گروه‌ها، مدیریت کاربران، آمار زنده سیستم و ارسال پیام‌های سراسری (Broadcast).
> 2. **مدیریت توکن‌ها**: ایجاد و ابطال توکن‌های امن و طولانی با نام و برچسب در تب اختصاصی پنل مدیریت، با هش امنیتی SHA-256 در دیتابیس.
> 3. **شخصی‌سازی برند**: تنظیم کامل نام برنامه، شعار، پیام خوش‌آمدگویی، تصویر لوگوی اصلی، آیکون مینیمال و بنر ورود در پنل مدیریت با اعمال لحظه‌ای در تمام صفحات.

---

### ۱. نمای کلی و اهداف پروژه

این تغییرات پیام‌رسان را از یک وب‌اپ ساده به یک پلتفرم ارتباطی جامع تبدیل می‌کند:
- **هسته توسعه‌پذیر (Headless & Extensible)**: فراهم‌سازی API استاندارد RESTful برای توسعه کلاینت‌های اختصاصی، ربات‌های هوشمند و اسکریپت‌های اتوماسیون.
- **امنیت در سطح سازمانی**: محافظت از تمامی اندپوینت‌ها با توکن‌های ۶۴ کاراکتری تصادفی مبتنی بر Bearer Authentication.
- **هویت بصری یکنواخت و حرفه‌ای**: حذف کادرهای مربعی محصورکننده لوگو، استفاده از آیکون مینیمال دوحبابی در فضاهای کوچک، و بزرگنمایی متقارن لوگو در صفحه انتظار و صفحه اصلی.
- **مستندات گیت‌هاب پیجز**: مستندسازی کامل به زبان فارسی در ساختار HTML/CSS گیت‌هاب پیجز و مارک‌داون برای آموزش ساخت بات و کلاینت.

### ۲. تجربه کاربری و طراحی بصری (UX & Visual Design)

#### اصلاح و جانمایی لوگوها
1. **صفحه اصلی چت (حالت خالی / بدون چت فعال)**:
   - حذف کامل کادر مربعی تیره (`w-28 h-28 bg-gradient... border rounded-3xl`).
   - نمایش لوگوی شفاف بدون مرز با اندازه چشم‌نواز (`height: 160px` یا `size: 140px`) و تراز دقیق در مرکز عمودی و افقی همراه با افکت محو ملایم پس‌زمینه.
   - استفاده از نام پویا (`systemConfig.appName`) و شعار سفارشی در زیر آن.
2. **صفحه بارگذاری و خوش‌آمدگویی (Splash)**:
   - حذف کادرهای مربعی اضافه، بزرگنمایی لوگوی شفاف و نمایش بدون مرز شبیه صفحه ورود.
3. **لوگوی مینیمال (Symbol)**:
   - بهره‌گیری مستقیم از تصویر نماد مینیمال (`/assets/aistudio/stargram-minimal.png`) در هدر سایدبار، کشوی منو، فاویکون و واترمارک‌ها بدون برش مصنوعی یا حاشیه ناخواسته.

#### پنل مدیریت: دو تب جدید و مدرن
1. **تب شخصی‌سازی برند و ظاهر (Branding & Identity)**:
   - فیلدهای ویرایش نام برنامه (پیش‌فرض: استارلی چت)، شعار پیام‌رسان، پیام خوش‌آمدگویی، نشانی لوگوی کامل، نشانی آیکون مینیمال و بنر ورود.
   - پیش‌نمایش زنده در همان تب و ذخیره مستقیم در پایگاه داده (`system_config`).
2. **تب توکن‌های امن API (API & Tokens)**:
   - دکمه «تولید توکن جدید» با قابلیت نام‌گذاری (مثلاً: «ربات اخبار»، «کلاینت دسکتاپ»، «اتوماسیون وب»).
   - نمایش توکن کامل فقط در لحظه تولید همراه با دکمه کپی فوری.
   - جدول فهرست توکن‌های فعال شامل نام، تاریخ ساخت، آخرین استفاده و دکمه ابطال فوری.
   - کارت راهنمای سریع استفاده با نمونه دستور `curl` و پیوند مستقیم به مستندات در GitHub Pages.

### ۳. معماری سیستم و مسیرهای API (REST Endpoints)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        External Clients & Bots                         │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Authorization: Bearer <API_TOKEN>
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        StarGram Server API                             │
│                                                                        │
│  ┌─────────────────────────┐  ┌─────────────────────────────────────┐  │
│  │   Client Endpoints      │  │        Management Endpoints         │  │
│  │  /api/v1/auth/login     │  │  /api/v1/admin/stats                │  │
│  │  /api/v1/auth/register  │  │  /api/v1/admin/users (CRUD)         │  │
│  │  /api/v1/auth/me        │  │  /api/v1/admin/chats (CRUD)         │  │
│  │  /api/v1/chats          │  │  /api/v1/admin/broadcast            │  │
│  │  /api/v1/messages       │  │  /api/v1/admin/tokens (Generate/Del)│  │
│  │  /api/v1/users/search   │  │  /api/v1/admin/config (Branding)    │  │
│  └─────────────────────────┘  └─────────────────────────────────────┘  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                 Database Layer (PostgreSQL / MySQL / Local)            │
│       Collections: users · chats · messages · system_config · api_keys │
└────────────────────────────────────────────────────────────────────────┘
```

#### اندپوینت‌های اصلی API پیاده‌سازی‌شده:
- **احراز هویت و کاربر (`/api/v1/auth/*`, `/api/v1/users`)**:
  - `POST /api/v1/auth/login`: ورود کاربران کلاینت با نام کاربری و رمزعبور و دریافت توکن نشست.
  - `POST /api/v1/auth/register`: ثبت‌نام کاربر جدید.
  - `GET /api/v1/auth/me`: دریافت اطلاعات کاربر جاری.
  - `GET /api/v1/users`: دریافت فهرست کاربران (با فیلتر جستجو).
  - `POST /api/v1/users`: ساخت کاربر توسط ادمین/ربات.
  - `PATCH /api/v1/users/:id`: ویرایش مشخصات، مسدودسازی یا اعطای نقش.
  - `DELETE /api/v1/users/:id`: حذف کاربر.
- **چت‌ها، کانال‌ها و گروه‌ها (`/api/v1/chats/*`)**:
  - `GET /api/v1/chats`: لیست گفتگوها.
  - `POST /api/v1/chats`: ساخت چت خصوصی، گروه یا کانال جدید.
  - `GET /api/v1/chats/:id`: دریافت جزئیات گفتگو و اعضا.
  - `DELETE /api/v1/chats/:id`: حذف گفتگو یا کانال.
- **پیام‌رسانی (`/api/v1/chats/:id/messages`)**:
  - `GET /api/v1/chats/:id/messages`: دریافت تاریخچه پیام‌ها با صفحه‌بندی (`limit`, `before`).
  - `POST /api/v1/chats/:id/messages`: ارسال پیام متنی، رسانه‌ای یا نظرسنجی.
  - `DELETE /api/v1/chats/:id/messages/:msgId`: حذف پیام.
  - `POST /api/v1/chats/:id/messages/:msgId/reactions`: ثبت واکنش ایموجی.
- **مدیریت سیستم و اطلاع‌رسانی (`/api/v1/admin/*`)**:
  - `GET /api/v1/admin/stats`: آمار کل کاربران، چت‌ها، پیام‌ها، و زمان فعالیت سرور.
  - `POST /api/v1/admin/broadcast`: ارسال اعلان سراسری سیستمی به تمام کاربران یا کانال‌ها.
  - `GET /api/v1/admin/tokens`: لیست توکن‌های API فعال.
  - `POST /api/v1/admin/tokens`: تولید توکن جدید ۶۴ بایتی ایمن با عنوان مشخص.
  - `DELETE /api/v1/admin/tokens/:id`: باطل‌سازی توکن.
  - `GET/PATCH /api/v1/admin/config`: دریافت و بروزرسانی تنظیمات برند و سیستم.

### ۴. ساختار مستندات در GitHub Pages و Help

1. **فایل `pages/help/api.html`**:
   - مستند کامل فارسی با استایل سازگار با سایت GitHub Pages.
   - بخش‌های راهنما:
     - مقدمه و اصول اتصال به API.
     - شیوه دریافت و ارسال هدر احراز هویت (`Authorization: Bearer <token>`).
     - جداول متدها، آدرس‌ها، پارامترهای ارسالی و نمونه خروجی JSON.
     - نمونه کدهای عملی با cURL، جاوااسکریپت (Node.js Fetch / Axios) و پایتون.
     - راهنمای ساخت ربات خبررسان و ساخت کلاینت چت سفارشی.
     - کدهای وضعیت و مدیریت خطاها (200, 400, 401, 403, 404, 500).
2. **به‌روزرسانی ناوبری سایت**:
   - افزودن پیوند «مستندات API» در نوار بالای `pages/index.html` و منوی کناری `pages/help/index.html`.
3. **فایل متنی در مخزن**:
   - ایجاد `/help/api.fa.md` و به‌روزرسانی `/help/README.md` برای دسترسی آسان در گیت‌هاب.
