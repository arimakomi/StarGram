# برنامه اجرایی مدیریت نشست‌ها، دسترسی اعلان‌ها و ارتقای API پیام‌رسان StarGram

این سند نقشه راه پیاده‌سازی کامل مدیریت نشست‌ها، شخصی‌سازی سطح اعلان‌ها برای هر دستگاه، افزودن اندپوینت‌های اختصاصی به REST API و بروزرسانی مستندات فنی را مشخص می‌کند.

---

## ۱. اهداف و نیازمندی‌ها
- **نمایش صحیح و زنده نشست‌ها:** نمایش کامل دستگاه فعلی و سایر دستگاه‌های متصل با متادیتای سیستم‌عامل، مرورگر، نوع دستگاه، زمان آخرین فعالیت و آدرس IP.
- **تفکیک دسترسی نوتیفیکیشن برای هر نشست:** تنظیم مجزا برای هر سشن شامل:
  1. فعال/غیرفعال بودن نوتیفیکیشن (`enabled`)
  2. نمایش متن و پیش‌نمایش پیام در اعلان‌ها (`previewText`)
  3. پخش صدای اعلان و زنگ (`sound`)
  4. بی‌صدا کردن موقت (۱ ساعت، ۸ ساعت، ۲ روز، دائم) (`muteUntil`)
- **رابط کاربری اختصاصی تلگرامی:** تب مجزای «دستگاه‌ها و نشست‌ها» در `SettingsModal` با تفکیک نشست جاری، دکمه خاتمه سایر نشست‌ها و کارت‌های کنترل هر دستگاه.
- **پکیج کامل اندپوینت‌های REST API:** افزودن مسیرهای دریافت سشن‌ها، ویرایش دسترسی نوتیفیکیشن و خاتمه نشست‌ها به `server.js`.
- **بروزرسانی کامل مستندات:** اعمال تغییرات در مستندات مارک‌داون (`help/api.fa.md`) و صفحه وب گیت‌هاب پیجز (`pages/help/api.html`).

---

## ۲. گام‌های پیاده‌سازی

### گام اول: تکمیل رابط کاربری تب نشست‌ها (`components/SettingsModal.tsx`)
- افزودن تب `sessions` («دستگاه‌ها و نشست‌ها») به هدر تب‌های مدال تنظیمات با آیکون `Laptop`.
- پیاده‌سازی ساختار تلگرامی:
  - **کارت دستگاه فعلی (این نشست):** نمایش آیکون دستگاه، نام سیستم‌عامل و مرورگر، شناسه/آی‌پی، بج سبز «آنلاین / همین دستگاه»، سوییچ‌های سریع فعال‌بودن نوتیفیکیشن، پیش‌نمایش متن پیام، صدای زنگ و بی‌صدا کردن سریع.
  - **دکمه خاتمه سایر نشست‌ها:** دکمه قرمز مشخص همراه با مدال تایید امنیتی دو مرحله‌ای.
  - **فهرست سایر دستگاه‌های فعال:** کارت‌های زیبا با زمان آخرین فعالیت به فارسی، وضعیت اعلان‌ها (روشن / بی‌صدا تا فلان تاریخ / خاموش)، دکمه تنظیم نوتیفیکیشن (باز شدن مدال ویرایش دسترسی‌های همان سشن) و دکمه قطع دسترسی.
  - **مدال تنظیم اختصاصی اعلان سشن:** امکان ویرایش دسترسی‌های نوتیفیکیشن نشست‌های دیگر از راه دور.

### گام دوم: یکپارچه‌سازی نشست و اعلان‌ها در سمت کلاینت (`App.tsx`)
- ثبت خودکار نشست جاری کاربر هنگام ورود یا لود برنامه از طریق `initOrUpdateCurrentSession`.
- گوش دادن به وضعیت نشست جاری: چنانچه نشست از دستگاه دیگری خاتمه داده شد، نمایش اعلان خروج و خروج امن کاربر.
- اتصال سیستم پخش اعلان و صدا در `App.tsx` به تنظیمات اختصاصی سشن جاری با استفاده از `getCachedLocalSessionNotifs()`.

### گام سوم: توسعه اندپوینت‌های REST API در سرور (`server.js`)
- پیاده‌سازی روت‌های احرازهویت‌شده تحت زیرمسیر `/api/v1/sessions`:
  - `GET /api/v1/sessions`: دریافت فهرست نشست‌های کاربر احرازهویت‌شده (با متادیتای سیستم‌عامل، مرورگر، آی‌پی، وضعیت اعلان‌ها و مشخص بودن سشن جاری).
  - `PATCH /api/v1/sessions/:id/notifications`: ویرایش تنظیمات دسترسی اعلان (enabled, previewText, sound, muteUntil).
  - `DELETE /api/v1/sessions/:id`: خاتمه دادن به یک نشست مشخص.
  - `POST /api/v1/sessions/terminate-others`: خاتمه دادن به تمام نشست‌های دیگر کاربر به جز نشست جاری.

### گام چهارم: بروزرسانی مستندات فنی و راهنما
- **فایل مارک‌داون `help/api.fa.md`:** افزودن بخش «مدیریت دستگاه‌ها و نشست‌ها (Sessions & Devices API)» با جداول متدها، پارامترهای ارسالی، نمونه کدهای درخواست و پاسخ JSON.
- **صفحه گیت‌هاب پیجز `pages/help/api.html`:** افزودن کارت‌ها، جداول و بلاک‌های کد مستندات API سشن‌ها در سایدبار و بدنه صفحه راهنما.

### گام پنجم: صحت‌سنجی و بیلد
- اجرای `lint_applet` و `compile_applet` جهت اطمینان از سلامت کدهای تایپ‌اسکریپت و بیلد برنامه.

## ۳. شاخص‌های موفقیت (Acceptance Criteria)
1. نشست‌های فعال در تب اختصاصی تنظیمات به درستی و بدون خطای رندرینگ لود شوند.
2. خاموش/روشن کردن صدا، پیش‌نمایش و اعلان روی همان دستگاه بلافاصله اثر کند و برای سشن‌های دیگر مجزا ذخیره شود.
3. خاتمه سایر نشست‌ها یا یک نشست خاص بلافاصله لیست را بروز کند.
4. اندپوینت‌های REST API در `server.js` با توکن‌های کاربر و ادمین پاسخ استاندارد ارسال کنند.
5. مستندات HTML و Markdown کاملاً همگام و حاوی نمونه پاسخ‌های واقعی باشند.
