۲. پیش‌نیازها و انتخاب روش نصب

  • سرور Linux با دسترسی root یا sudo برای نصب‌کننده تعاملی؛
  • Node.js نسخه ۱۸ یا بالاتر و npm؛ نصب‌کننده در صورت نیاز Node.js 20 LTS را نصب می‌کند؛
  • اتصال اینترنت برای دریافت سورس و وابستگی‌ها؛
  • برای حالت SQL، یک سرور PostgreSQL یا MySQL/MariaDB در دسترس؛
  • برای سرویس systemd خودکار، سیستم‌عامل باید systemd داشته باشد.

برای VPS تازه، نصب‌کننده تعاملی ساده‌ترین گزینه است. نصب دستی زمانی مناسب است که بخواهید وابستگی‌ها، متغیرهای محیطی یا اجرای سرویس را خودتان مدیریت کنید. داده JSON برای نصب سریع کار می‌کند؛ برای سرویس مهم و پرترافیک، پایگاه داده SQL و برنامه پشتیبان‌گیری مستقل را در نظر بگیرید.

۳. نصب سریع روی لینوکس

اسکریپت نصب را با دسترسی مدیر اجرا کنید. فرمان نخست اسکریپت را از شاخه main می‌گیرد و نصب را آغاز می‌کند:

sudo bash <(curl -fsSL https://raw.githubusercontent.com/arimakomi/StarGram/main/setup.sh)

اگر shell شما process substitution را پشتیبانی نمی‌کند، دو مرحله‌ای اجرا کنید:

curl -fsSL https://raw.githubusercontent.com/arimakomi/StarGram/main/setup.sh -o setup.sh
sudo bash setup.sh

پاسخ به پرسش‌های نصب‌کننده

  1. پورت HTTP: به‌طور پیش‌فرض 3000 است. اگر اشغال است، شماره آزاد 1 تا 65535 انتخاب کنید.
  2. نام مدیر: ۳ تا ۳۲ نویسه، بدون فاصله یا اسلش.
  3. رمز مدیر: حداقل ۶ نویسه؛ رمز قوی و یکتا انتخاب کنید. اگر خالی بگذارید، نصب‌کننده یک مقدار تصادفی می‌سازد و فقط در خروجی همان لحظه نشان می‌دهد؛ آن را ذخیره کنید.
  4. نوع پایگاه داده: local برای JSON، postgres برای PostgreSQL یا mysql برای MySQL/MariaDB.
  5. تنظیمات اتصال SQL: میزبان، پورت، نام پایگاه داده و حساب SQL را وارد کنید. اگر رمز خالی باشد نصب‌کننده آن را تولید و در فایل محدودشده .env ذخیره می‌کند.

نصب‌کننده وابستگی‌ها را نصب می‌کند، build فرانت‌اند را اجرا می‌کند، حساب مدیر را مقداردهی می‌کند و اگر systemd موجود باشد سرویس stargram را فعال می‌کند. سپس فرمان مدیریت stargram را در مسیر اجرایی سیستم قرار می‌دهد.

نصب غیرتعاملی با ذخیره JSON

sudo NONINTERACTIVE=1 PORT=3000 \
  ADMIN_USER=admin ADMIN_PASS='Replace-With-A-Long-Unique-Password' \
  DB_TYPE=local bash setup.sh

این نمونه زمانی مناسب است که فایل setup.sh را در پوشه پروژه گرفته‌اید. برای استفاده امن، رمز نمونه را با رمز واقعی و قوی جایگزین کنید و آن را در history یا فایل عمومی قرار ندهید.

پایان نصب

نصب‌کننده IP و پورت دسترسی را چاپ می‌کند. پیش از استفاده عمومی، دامنه و HTTPS را طبق فصل دامنه و HTTPS تنظیم کنید. اگر سرویس خودکار اجرا نشد، فرمان‌های وضعیت و log در فصل مدیریت سرور آمده‌اند.

۴. نصب دستی

Node.js 18+، npm و Git باید نصب باشند. مخزن را دریافت و وابستگی‌ها را نصب کنید:

git clone https://github.com/arimakomi/StarGram.git
cd StarGram
npm ci
cp .env.example .env

ویرایش کنید و حداقل این مقادیر را در .env قرار دهید:

PORT=3000
DB_TYPE=local
ADMIN_USER=admin
ADMIN_PASS=ReplaceWithALongUniquePassword

سپس build، مقداردهی حساب مدیر و اجرای سرور:

npm run build
node server.js --init
npm start

فرمان --init حساب مدیر مشخص‌شده در ADMIN_USER را ایجاد می‌کند؛ اگر حساب وجود داشته باشد، رمز آن را با ADMIN_PASS تنظیم می‌کند. برای اجرای طولانی‌مدت روی سرور، سرویس systemd یا مدیر فرایند مناسب راه‌اندازی کنید. فرمان npm start به‌تنهایی، ترمینال جاری را اشغال می‌کند.

توسعه محلی

در یک ترمینال API سرور را با npm start اجرا کنید و در ترمینال دوم npm run dev را بزنید. Vite درخواست‌های /api را به سرور محلی روی پورت 3000 می‌فرستد.

۵. پایگاه داده

DB_TYPEموتورذخیره داده
localJSONdata/stargram_db.json
postgresPostgreSQLپایگاه داده SQL تنظیم‌شده
mysqlMySQL / MariaDBپایگاه داده SQL تنظیم‌شده

مقادیر SQL را می‌توان با متغیرهای محیطی تنظیم کرد:

DB_TYPE=postgres
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=stargram
DB_USER=stargram
DB_PASS=ChangeThisPassword

برای MySQL/MariaDB مقدار DB_TYPE=mysql و پورت متداول 3306 است. DATABASE_URL نیز پشتیبانی می‌شود و اگر تنظیم شده باشد بر متغیرهای اتصال جداگانه اولویت دارد. مقادیر واقعی رمز و آدرس پایگاه داده را در GitHub commit نکنید.

سرور در صورت عدم دسترسی به SQL می‌تواند به ذخیره‌سازی JSON محلی بازگردد. از روی باز شدن صفحه به‌تنهایی نتیجه نگیرید که SQL متصل است؛ وضعیت موتور را در پنل مدیریت یا با sudo stargram status بررسی کنید.

۶. دامنه، HTTPS و استقرار عمومی

سرور برنامه HTTP ارائه می‌کند و TLS را خودش خاتمه نمی‌دهد. برای دسترسی عمومی، دامنه را به IP سرور وصل کنید و Nginx یا Caddy را به‌عنوان reverse proxy با گواهی معتبر HTTPS تنظیم کنید. پورت برنامه را از اینترنت عمومی ببندید یا دسترسی آن را محدود کنید و فقط پورت‌های وب proxy را باز بگذارید.

  • برای محیط عمومی از HTTPS استفاده کنید؛ مرورگر برای اعلان و PWA به secure context نیاز دارد.
  • فایل .env، پوشه data و پشتیبان‌ها را از دسترسی وب مستقیم خارج نگه دارید.
  • برای uploadهای بزرگ، محدودیت بدنه درخواست proxy را بررسی کنید.
  • پس از تنظیم DNS و TLS، ورود، ارسال پیام و اتصال WebSocket/API را از بیرون سرور آزمایش کنید.
  • برای دستورهای دقیق proxy، از مستندات نسخه توزیع و reverse proxy خود استفاده کنید.
