۱۷. پنل مدیریت

کاربری که مدیر سامانه است می‌تواند پنل مدیریت را از منوی برنامه باز کند. پنل برای تنظیم و نظارت بر کاربران، گزارش‌ها، گروه‌ها، کانال‌ها و تنظیمات سیستم است. دسترسی عادی نباید اختیار مدیر داشته باشد.

  • مدیریت حساب‌ها و وضعیت کاربران؛
  • رسیدگی به گزارش‌ها و مدیریت گفتگوهای گروهی/کانالی؛
  • تنظیمات سامانه و اتصال اختیاری Gemini؛
  • خروجی و بازیابی پشتیبان JSON در حالت محلی.

کلید API Gemini را فقط در پنل/تنظیم امن سرور وارد کنید؛ هرگز آن را در فایل‌های فرانت‌اند یا مخزن عمومی قرار ندهید. درخواست دستیار فقط وقتی ارسال می‌شود که قابلیت فعال و استفاده شود.

۱۸. مدیریت سرور با فرمان stargram

نصب‌کننده لینوکس فرمان مدیریت را ایجاد می‌کند. بسته به کاربر و دسترسی سرویس، آن را با sudo اجرا کنید:

sudo stargram                 # Open the management menu
sudo stargram status          # Service and database status
sudo stargram start
sudo stargram stop
sudo stargram restart
sudo stargram logs             # Recent logs
sudo stargram logs follow      # Follow logs live
sudo stargram health           # Check the health endpoint
sudo stargram port 8080        # Change the HTTP port
sudo stargram backup           # Create a backup
sudo stargram admin            # Reset administrator credentials
sudo stargram update           # Update application code
sudo stargram help

منوی تعاملی، promptها و خروجی ترمینال به انگلیسی هستند. زیر‌فرمان port پیکربندی پورت را تغییر می‌دهد؛ پس از تغییر، reverse proxy و firewall را نیز هماهنگ کنید. دستور uninstall را فقط پس از backup و بررسی داده‌ها اجرا کنید.

۱۹. به‌روزرسانی

برای نصب‌های ایجادشده با اسکریپت، از این فرمان استفاده کنید:

sudo stargram update

به‌روزرسانی نسخه شاخه main را مستقیم از GitHub دریافت می‌کند؛ بنابراین پوشه نصب لازم نیست Git repository باشد و خطای fatal: not a git repository از اجرای pull در پوشه غیر Git پیش نمی‌آید. فرمان از داده‌ها backup می‌گیرد، فایل‌های برنامه را تازه می‌کند، وابستگی‌ها را نصب و build را اجرا می‌کند، schema را آماده می‌کند و در صورت وجود systemd سرویس را restart می‌کند.

مواردی که حفظ می‌شوند: data/، backups/، فایل‌های .env و node_modules/. تغییرات محلی کد ممکن است بازنویسی شوند. قبل از آپدیت، پشتیبان مستقل بگیرید و سفارشی‌سازی کد را ثبت کنید.

اگر نصب را دستی انجام داده‌اید و مسیر Git checkout است، روش به‌روزرسانی شما می‌تواند متفاوت باشد؛ از فرمان مدیریت همین نصب یا روش نگهداری خودتان استفاده کنید و هم‌زمان دو روش را روی یک سرور اجرا نکنید.

۲۰. پشتیبان‌گیری و بازیابی

در حالت JSON، داده اصلی در data/stargram_db.json است. فرمان sudo stargram backup نسخه فشرده می‌سازد. در SQL، فرمان از ابزار dump موتور پایگاه داده استفاده می‌کند؛ utilityهای متناظر باید روی سرور نصب و اتصال دسترسی‌پذیر باشد.

پنل مدیریت نیز برای حالت محلی امکانات خروجی و بازیابی JSON دارد. بازیابی را ابتدا روی نسخه آزمایشی یا پس از گرفتن backup از داده فعلی انجام دهید؛ فایل نامتناسب یا قدیمی ممکن است داده تازه‌تر را جایگزین کند.

  • فایل‌های backup را از document root وب دور نگه دارید.
  • پشتیبان را روی همان دیسکی که داده اصلی است تنها نسخه نگه ندارید.
  • برای SQL، علاوه بر برنامه StarGram، پایگاه داده را در برنامه backup دوره‌ای وارد کنید.
  • دوره‌ای مطمئن شوید backup قابل خواندن و بازیابی است.
