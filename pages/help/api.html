مستندات فنی توسعه‌دهندگان API v1

مستندات کامل REST API و کلیدهای دسترسی

با استفاده از API قدرتمند و امن StarGram، می‌توانید کلاینت‌های دسکتاپ و موبایل سفارشی بسازید، ربات‌های هوشمند و خبرخوان متصل کنید و پیام‌رسان را به صورت کاملاً برنامه‌ریزی‌شده مدیریت نمایید.

راهنمای StarGram نمای کلی و فهرست مستندات کامل API v1 نصب و استقرار حساب و گفتگوهای خصوصی گروه‌ها کانال‌ها پیام‌ها و محتوا تنظیمات و وب‌اپ مدیریت سرور امنیت و رفع اشکال

۱. اصول پایه و نشانی سرور (Base URL)

کلیه ارتباطات با API پیام‌رسان از طریق پروتکل استاندارد HTTP/HTTPS با تبادل داده در قالب JSON صورت می‌گیرد.

آدرس پایه در سرور محلی یا سرور اختصاصی:
http://localhost:3000/api/v1 یا https://chat.yourdomain.com/api/v1

تمام درخواست‌های ارسالی با متد POST، PATCH یا DELETE باید دارای هدر Content-Type: application/json باشند.

۲. احراز هویت و توکن‌های امن (Authentication)

تمام اندپوینت‌های مدیریتی و دسترسی به اطلاعات با توکن‌های امن و طولانی محافظت می‌شوند. احراز هویت از طریق استاندارد Bearer Token در هدر Authorization درخواست‌ها صورت می‌گیرد: 

Authorization: Bearer stg_live_8f3a9b1c7e...

شیوه ساخت کلید در پنل مدیریت

  1. با حساب مدیر وارد پیام‌رسان شوید.
  2. از منوی کناری (سه خط) گزینه «پنل مدیریت سیستم» را باز کنید.
  3. به برگه «مدیریت API و توکن‌ها» بروید.
  4. روی دکمه «تولید توکن امن جدید» کلیک کرده، نام کاربری یا هدف کلید را وارد کرده و مدت اعتبار را مشخص کنید.
  5. کلید تولیدشده ۶۴ کاراکتری را همان لحظه کپی کرده و ذخیره نمایید.

۳. فهرست اندپوینت‌های API v1

الف) پایش و مدیریت سیستم (System & Admin)

متد مسیر توضیحات
GET /api/v1/admin/stats آمار زنده: شمار کاربران، چت‌ها، پیام‌ها، آپتایم و وضعیت دیتابیس
GET /api/v1/admin/config دریافت تنظیمات برند (نام، لوگوها، شعار) و محدودیت‌های ثبت‌نام
PATCH /api/v1/admin/config به‌روزرسانی نام برنامه، شعار، آیکون مینیمال، لوگوی کامل و سوئیچ‌ها
POST /api/v1/admin/broadcast ارسال پیام سراسری اعلان (Broadcast) به تمام کانال‌ها و گروه‌ها
GET /api/v1/admin/tokens دریافت فهرست توکن‌های فعال API و زمان آخرین استفاده
POST /api/v1/admin/tokens تولید توکن جدید امن با نام و مدت اعتبار
DELETE /api/v1/admin/tokens/:id باطل‌سازی و حذف دائم یک توکن API

ب) مدیریت کاربران (Users)

متد مسیر توضیحات
GET /api/v1/users لیست کاربران با پشتیبانی از فیلتر search, role, limit
GET /api/v1/users/:id مشاهده مشخصات یک کاربر خاص بر اساس شناسه یا نام کاربری
POST /api/v1/users ساخت مستقیم کاربر جدید (با تعیین نقش user یا admin)
PATCH /api/v1/users/:id ویرایش نام نمایشی، بیوگرافی، مسدودسازی، تغییر نقش یا تغییر رمز
DELETE /api/v1/users/:id حذف کاربر از سیستم

ج) چت‌ها، گروه‌ها و کانال‌ها (Chats)

متد مسیر توضیحات
GET /api/v1/chats فهرست گفتگوها (با فیلتر نوع private, group, channel)
POST /api/v1/chats ایجاد گفتگوی خصوصی جدید، گروه یا کانال همراه با اعضا
GET /api/v1/chats/:id دریافت جزئیات گفتگو، اعضا و آخرین وضعیت
DELETE /api/v1/chats/:id حذف یک گفتگو یا کانال

د) ارسال و مدیریت پیام‌ها (Messages)

متد مسیر توضیحات
GET /api/v1/chats/:id/messages دریافت تاریخچه پیام‌ها با صفحه‌بندی (limit, before)
POST /api/v1/chats/:id/messages ارسال پیام متنی، تصویر، صدا، نظرسنجی یا پاسخ (Reply)
DELETE /api/v1/chats/:id/messages/:msgId حذف پیام مشخص
POST /api/v1/chats/:id/messages/:msgId/reactions ثبت واکنش ایموجی (مانند ❤️, 👍, 🔥) روی پیام

هـ) احراز هویت کلاینت‌ها (Auth Endpoints)

برای ساخت اپلیکیشن‌هایی که کاربران وارد حساب خود می‌شوند:

POST /api/v1/auth/login
Body: { "username": "ali", "password": "MyPassword123" }
Response: { "success": true, "token": "...", "user": { ... } }
POST /api/v1/auth/register
Body: { "username": "sara", "password": "SecurePassword", "displayName": "سارا" }
GET /api/v1/auth/me
Header: Authorization: Bearer <USER_TOKEN>

و) مدیریت نشست‌ها و دسترسی اعلان‌ها (Sessions & Notifications)

امکان دریافت دستگاه‌های متصل به حساب، خاتمه دادن به سشن‌ها و تفکیک دسترسی نوتیفیکیشن برای هر دستگاه:

متد مسیر توضیحات
GET /api/v1/sessions فهرست نشست‌های فعال کاربر جاری به همراه متادیتای سیستم‌عامل، مرورگر و تنظیمات نوتیف
GET /api/v1/sessions/:id دریافت جزئیات یک نشست مشخص با شناسه :id
PATCH /api/v1/sessions/:id/notifications تنظیم دسترسی اعلان این دستگاه (enabled, previewText, sound, muteUntil)
DELETE /api/v1/sessions/:id خاتمه دادن به نشست دستگاه مشخص و قطع دسترسی آن
POST /api/v1/sessions/terminate-others خاتمه دادن به تمام نشست‌های فعال دیگر به جز نشست جاری
نمونه بدنه درخواست برای تغییر دسترسی اعلان نشست: 
PATCH /api/v1/sessions/sess_1740000000_abc/notifications
Header: Authorization: Bearer <USER_TOKEN>
Content-Type: application/json

{
  "enabled": true,
  "previewText": false,
  "sound": true,
  "muteUntil": 1740100000000
}

۴. نمونه کدهای عملی

۱) ارسال پیام با جاوااسکریپت (Node.js یا مرورگر)

const API_TOKEN = 'stg_live_YOUR_TOKEN_HERE';
const BASE_URL = 'http://localhost:3000/api/v1';

async function sendMessage(chatId, text) {
  const response = await fetch(`\${BASE_URL}/chats/\${chatId}/messages`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer \${API_TOKEN}`
    },
    body: JSON.stringify({ text })
  });
  const data = await response.json();
  console.log('پیام ارسال شد:', data);
  return data;
}

// اجرا:
sendMessage('ch_1742080000000_abc', 'سلام! این پیام از طریق API فرستاده شد 🚀');

۲) ساخت ربات اطلاع‌رسانی با پایتون (Python)

import requests

API_TOKEN = "stg_live_YOUR_TOKEN_HERE"
BASE_URL = "http://localhost:3000/api/v1"

headers = {
    "Authorization": f"Bearer {API_TOKEN}",
    "Content-Type": "application/json"
}

# دریافت آمار سیستم
stats = requests.get(f"{BASE_URL}/admin/stats", headers=headers).json()
print("آمار کاربران:", stats["stats"]["totalUsers"])

# ارسال اطلاعیه سراسری
payload = {
    "title": "به‌روزرسانی سرور",
    "message": "سرور در ساعت ۲ بامداد به مدت ۱۰ دقیقه ارتقا خواهد یافت.",
    "target": "all"
}
res = requests.post(f"{BASE_URL}/admin/broadcast", json=payload, headers=headers)
print("نتیجه ارسال سراسری:", res.json())

۳) آزمایش فوری با cURL در ترمینال

# دریافت آمار سرور
curl -X GET "http://localhost:3000/api/v1/admin/stats" \
  -H "Authorization: Bearer stg_live_YOUR_TOKEN"

# ارسال پیام به گفتگو
curl -X POST "http://localhost:3000/api/v1/chats/ch_123/messages" \
  -H "Authorization: Bearer stg_live_YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "تست پیام از ترمینال لینوکس"}'

۵. کدهای وضعیت HTTP و رفع خطا

  • 200 OK: درخواست با موفقیت پردازش شد.
  • 201 Created: کاربر، گفتگو یا پیام جدید با موفقیت ایجاد گردید.
  • 400 Bad Request: فیلدهای الزامی (مانند متن پیام یا نام کاربری) ارسال نشده یا نامعتبر است.
  • 401 Unauthorized: هدر Authorization ارسال نشده، منقضی شده یا نامعتبر است.
  • 403 Forbidden: این عملیات نیاز به دسترسی ادمین دارد یا حساب کاربری مسدود شده است.
  • 404 Not Found: گفتگو، کاربر یا پیام مورد نظر در سیستم یافت نشد.
  • 429 Too Many Requests: تعداد تلاش‌ها برای ورود بیش از حد مجاز بوده است.
  • 500 Server Error: خطای داخلی در سرور یا دیتابیس رخ داده است.
