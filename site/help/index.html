راهنمای کامل StarGram

۱. آشنایی با StarGram

StarGram یک پیام‌رسان وب خودمیزبان است. مدیر پروژه آن را روی سرور لینوکس نصب می‌کند و کاربران از مرورگر به همان سرور وصل می‌شوند. رابط فعلی فارسی و راست‌چین است. مخزن کد با مجوز MIT منتشر شده است.

  • گفتگوهای خصوصی، گروه‌ها و کانال‌ها؛
  • پیام متنی، پاسخ، ویرایش، واکنش، سنجاق و ارسال مجدد؛
  • تصویر، پیام صوتی، نظرسنجی و استوری؛
  • تم، پس‌زمینه گفتگو، اعلان مرورگر و نصب PWA؛
  • پنل مدیر، فرمان خط فرمان، پشتیبان‌گیری و به‌روزرسانی؛
  • ذخیره‌سازی با PostgreSQL، MySQL/MariaDB یا فایل JSON محلی.
GitHub Pages فقط همین سایت معرفی و راهنما را میزبانی می‌کند. خود پیام‌رسان به Node.js و یک سرور دارای API نیاز دارد؛ GitHub Pages جایگزین سرور StarGram نیست.

۲. پیش‌نیازها و انتخاب روش نصب

  • سرور Linux با دسترسی root یا sudo برای نصب‌کننده تعاملی؛
  • Node.js نسخه ۱۸ یا بالاتر و npm؛ نصب‌کننده در صورت نیاز Node.js 20 LTS را نصب می‌کند؛
  • اتصال اینترنت برای دریافت سورس و وابستگی‌ها؛
  • برای حالت SQL، یک سرور PostgreSQL یا MySQL/MariaDB در دسترس؛
  • برای سرویس systemd خودکار، سیستم‌عامل باید systemd داشته باشد.

برای VPS تازه، نصب‌کننده تعاملی ساده‌ترین گزینه است. نصب دستی زمانی مناسب است که بخواهید وابستگی‌ها، متغیرهای محیطی یا اجرای سرویس را خودتان مدیریت کنید. داده JSON برای نصب سریع کار می‌کند؛ برای سرویس مهم و پرترافیک، پایگاه داده SQL و برنامه پشتیبان‌گیری مستقل را در نظر بگیرید.

۳. نصب سریع روی لینوکس

اسکریپت نصب را با دسترسی مدیر اجرا کنید. فرمان نخست اسکریپت را از شاخه main می‌گیرد و نصب را آغاز می‌کند:

sudo bash <(curl -fsSL https://raw.githubusercontent.com/arimakomi/StarGram/main/setup.sh)

اگر shell شما process substitution را پشتیبانی نمی‌کند، دو مرحله‌ای اجرا کنید:

curl -fsSL https://raw.githubusercontent.com/arimakomi/StarGram/main/setup.sh -o setup.sh
sudo bash setup.sh

پاسخ به پرسش‌های نصب‌کننده

  1. پورت HTTP: به‌طور پیش‌فرض 3000 است. اگر اشغال است، شماره آزاد 1 تا 65535 انتخاب کنید.
  2. نام مدیر: ۳ تا ۳۲ نویسه، بدون فاصله یا اسلش.
  3. رمز مدیر: حداقل ۶ نویسه؛ رمز قوی و یکتا انتخاب کنید. اگر خالی بگذارید، نصب‌کننده یک مقدار تصادفی می‌سازد و فقط در خروجی همان لحظه نشان می‌دهد؛ آن را ذخیره کنید.
  4. نوع پایگاه داده: local برای JSON، postgres برای PostgreSQL یا mysql برای MySQL/MariaDB.
  5. تنظیمات اتصال SQL: میزبان، پورت، نام پایگاه داده و حساب SQL را وارد کنید. اگر رمز خالی باشد نصب‌کننده آن را تولید و در فایل محدودشده .env ذخیره می‌کند.

نصب‌کننده وابستگی‌ها را نصب می‌کند، build فرانت‌اند را اجرا می‌کند، حساب مدیر را مقداردهی می‌کند و اگر systemd موجود باشد سرویس stargram را فعال می‌کند. سپس فرمان مدیریت stargram را در مسیر اجرایی سیستم قرار می‌دهد.

نصب غیرتعاملی با ذخیره JSON

sudo NONINTERACTIVE=1 PORT=3000 \
  ADMIN_USER=admin ADMIN_PASS='Replace-With-A-Long-Unique-Password' \
  DB_TYPE=local bash setup.sh

این نمونه زمانی مناسب است که فایل setup.sh را در پوشه پروژه گرفته‌اید. برای استفاده امن، رمز نمونه را با رمز واقعی و قوی جایگزین کنید و آن را در history یا فایل عمومی قرار ندهید.

پایان نصب

نصب‌کننده IP و پورت دسترسی را چاپ می‌کند. پیش از استفاده عمومی، دامنه و HTTPS را طبق فصل دامنه و HTTPS تنظیم کنید. اگر سرویس خودکار اجرا نشد، فرمان‌های وضعیت و log در فصل مدیریت سرور آمده‌اند.

۴. نصب دستی

Node.js 18+، npm و Git باید نصب باشند. مخزن را دریافت و وابستگی‌ها را نصب کنید:

git clone https://github.com/arimakomi/StarGram.git
cd StarGram
npm ci
cp .env.example .env

ویرایش کنید و حداقل این مقادیر را در .env قرار دهید:

PORT=3000
DB_TYPE=local
ADMIN_USER=admin
ADMIN_PASS=ReplaceWithALongUniquePassword

سپس build، مقداردهی حساب مدیر و اجرای سرور:

npm run build
node server.js --init
npm start

فرمان --init حساب مدیر مشخص‌شده در ADMIN_USER را ایجاد می‌کند؛ اگر حساب وجود داشته باشد، رمز آن را با ADMIN_PASS تنظیم می‌کند. برای اجرای طولانی‌مدت روی سرور، سرویس systemd یا مدیر فرایند مناسب راه‌اندازی کنید. فرمان npm start به‌تنهایی، ترمینال جاری را اشغال می‌کند.

توسعه محلی

در یک ترمینال API سرور را با npm start اجرا کنید و در ترمینال دوم npm run dev را بزنید. Vite درخواست‌های /api را به سرور محلی روی پورت 3000 می‌فرستد.

۵. پایگاه داده

DB_TYPEموتورذخیره داده
localJSONdata/stargram_db.json
postgresPostgreSQLپایگاه داده SQL تنظیم‌شده
mysqlMySQL / MariaDBپایگاه داده SQL تنظیم‌شده

مقادیر SQL را می‌توان با متغیرهای محیطی تنظیم کرد:

DB_TYPE=postgres
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=stargram
DB_USER=stargram
DB_PASS=ChangeThisPassword

برای MySQL/MariaDB مقدار DB_TYPE=mysql و پورت متداول 3306 است. DATABASE_URL نیز پشتیبانی می‌شود و اگر تنظیم شده باشد بر متغیرهای اتصال جداگانه اولویت دارد. مقادیر واقعی رمز و آدرس پایگاه داده را در GitHub commit نکنید.

سرور در صورت عدم دسترسی به SQL می‌تواند به ذخیره‌سازی JSON محلی بازگردد. از روی باز شدن صفحه به‌تنهایی نتیجه نگیرید که SQL متصل است؛ وضعیت موتور را در پنل مدیریت یا با sudo stargram status بررسی کنید.

۶. دامنه، HTTPS و استقرار عمومی

سرور برنامه HTTP ارائه می‌کند و TLS را خودش خاتمه نمی‌دهد. برای دسترسی عمومی، دامنه را به IP سرور وصل کنید و Nginx یا Caddy را به‌عنوان reverse proxy با گواهی معتبر HTTPS تنظیم کنید. پورت برنامه را از اینترنت عمومی ببندید یا دسترسی آن را محدود کنید و فقط پورت‌های وب proxy را باز بگذارید.

  • برای محیط عمومی از HTTPS استفاده کنید؛ مرورگر برای اعلان و PWA به secure context نیاز دارد.
  • فایل .env، پوشه data و پشتیبان‌ها را از دسترسی وب مستقیم خارج نگه دارید.
  • برای uploadهای بزرگ، محدودیت بدنه درخواست proxy را بررسی کنید.
  • پس از تنظیم DNS و TLS، ورود، ارسال پیام و اتصال WebSocket/API را از بیرون سرور آزمایش کنید.
  • برای دستورهای دقیق proxy، از مستندات نسخه توزیع و reverse proxy خود استفاده کنید.
خود مخزن GitHub Pages برای همین سایت راهنما استفاده می‌شود؛ برنامه StarGram روی سرور جداگانه شما اجرا می‌شود.

۷. حساب و پروفایل

نشانی سرور StarGram را در مرورگر باز کنید. با نام کاربری و رمز عبور وارد شوید. اگر ثبت‌نام در صفحه ورود فعال باشد، می‌توانید حساب بسازید؛ در غیر این صورت از مدیر سرور حساب بخواهید.

از منوی کناری پروفایل را باز کنید تا اطلاعات و تصویر خود را تغییر دهید. نام کاربری برای پیدا کردن حساب به کار می‌رود. برای خروج از دستگاه مشترک، از تنظیمات گزینه خروج را بزنید. خروج از حساب، حساب را حذف نمی‌کند.

اگر رمز مدیر را گم کرده‌اید، مدیر سرور می‌تواند مقدار ADMIN_PASS را در محیط تنظیم و node server.js --init را اجرا کند. این فرمان حساب مدیر تعیین‌شده در ADMIN_USER را ایجاد یا رمز آن را بازنشانی می‌کند.

۸. محیط و فهرست گفتگو

نوار کناری فهرست گفتگوها و دسترسی به جستجو، استوری‌ها، پروفایل، پیام‌های ذخیره‌شده و تنظیمات را فراهم می‌کند. زبانه‌های فهرست گفتگو را بر اساس همه، خصوصی، گروه، کانال و ذخیره‌شده فیلتر می‌کنند. نشان کنار گفتگو یا زبانه، پیام نخوانده را مشخص می‌کند.

از جستجوی بالای فهرست برای یافتن کاربران، گروه‌ها یا کانال‌هایی که قابل دسترسی یا عمومی هستند استفاده کنید. برای گزینه‌های یک گفتگو، منوی آن را باز کنید؛ روی موبایل ممکن است لمس طولانی جای کلیک راست را بگیرد.

در نمایش موبایل، گفتگو تمام صفحه می‌شود. برای بازگشت به فهرست از دکمه برگشت رابط استفاده کنید.

۹. گفتگوی خصوصی

  1. نام یا شناسه کاربر را در نوار جستجو وارد کنید.
  2. نتیجه را انتخاب کنید تا گفتگو باز شود.
  3. پیام را در کادر پایین بنویسید و ارسال کنید.

برای پاسخ، ویرایش پیام خود، واکنش یا ارسال مجدد، منوی پیام را باز کنید. منوی گفتگو ابزارهایی مانند سنجاق، بی‌صدا، بایگانی، علامت‌گذاری به‌عنوان خوانده‌شده و پاک‌کردن تاریخچه را ارائه می‌کند. گزینه‌ها با توجه به نوع گفتگو فرق دارند.

پاک‌کردن تاریخچه با بایگانی فرق دارد و ممکن است برگشت‌پذیر نباشد. پنجره تأیید را بخوانید؛ اگر فقط می‌خواهید گفتگو از فهرست اصلی کنار برود، از بایگانی استفاده کنید.

۱۰. گروه‌ها

ساخت گروه

  1. منوی کناری را باز و ساخت گروه را انتخاب کنید.
  2. نام، توضیح اختیاری و تصویر را وارد کنید.
  3. نوع را تعیین کنید: خصوصی برای عضویت با دعوت، یا عمومی با شناسه قابل جستجو.
  4. برای گروه عمومی یک شناسه وارد کنید؛ فقط حروف لاتین، عدد و زیرخط پذیرفته می‌شود.
  5. مرحله انتخاب مخاطبان را باز کنید، اعضا را انتخاب و ساخت را تأیید کنید. دعوت اعضا اختیاری است و بعداً نیز می‌توان گروه را مدیریت کرد.

دعوت و عضویت

برای خصوصی‌ها از لینک دعوت یا ابزارهای مدیریت اعضا استفاده کنید. عمومی‌ها با نام/شناسه قابل جستجو هستند. دریافت‌کننده لینک باید آن را در مرورگر باز کند و گزینه پیوستن را بزند.

مدیریت و گفتگو

از منوی اطلاعات گروه، نام و توضیح را ویرایش و اعضا یا مدیران را مدیریت کنید. ابزارهای در دسترس به نقش شما وابسته‌اند. در گروه برای اشاره به شخص، @ را تایپ و عضو را از فهرست پیشنهادها انتخاب کنید. اگر کادر ارسال در دسترس نیست، احتمالاً ارسال برای نقش شما محدود شده است.

عمومی بودن فقط پیدا شدن و پیوستن را آسان می‌کند؛ اعتبار یا امنیت محتوای گروه را تضمین نمی‌کند.

۱۱. کانال‌ها

کانال برای انتشار پیام به مشترکان است. سازنده و مدیران مجاز می‌توانند پیام بفرستند؛ مشترکان محتوا را دنبال می‌کنند.

ساخت کانال

  1. در منوی کناری ساخت کانال را بزنید.
  2. نام، توضیح و در صورت تمایل تصویر انتخاب کنید.
  3. مخاطبان مورد نظر را انتخاب و کانال را بسازید.

عمومی یا خصوصی

از ویرایش کانال، بخش نوع کانال را باز کنید. کانال خصوصی با لینک دعوت قابل دسترسی است. کانال عمومی شناسه دارد و در جستجو پیدا می‌شود.

مدیریت کانال

بسته به مجوز، از صفحه ویرایش می‌توانید نام و تصویر را تغییر دهید؛ امضای پیام‌ها یا نمایش پروفایل نویسنده را روشن کنید؛ واکنش‌ها را محدود کنید؛ لینک دعوت بسازید یا لغو کنید؛ مدیران، مشترکان و کاربران حذف‌شده را ببینید؛ و اقدامات اخیر را بررسی کنید. سازنده امکان حذف کانال را دارد. این اقدام را با دقت انجام دهید.

انتشار و عضویت

اگر مجوز انتشار دارید، پیام را از کادر کانال ارسال کنید. برای پیوستن به عمومی‌ها از جستجو یا شناسه استفاده کنید؛ برای خصوصی‌ها لینک معتبر لازم است. تعداد بازدید پیام کانال ممکن است نمایش داده شود.

۱۲. پیام‌ها و رسانه

متن و کلیدهای صفحه‌کلید

متن را در کادر پایین گفتگو بنویسید. با تنظیم پیش‌فرض «ارسال با Enter»، Enter پیام را می‌فرستد و Shift+Enter خط جدید می‌سازد. اگر این تنظیم خاموش باشد، Enter خط جدید و Ctrl+Enter در Windows/Linux یا Cmd+Enter در macOS فرمان ارسال است.

ابزارهای پیام

  • پاسخ: پیام اصلی به پاسخ پیوست می‌شود.
  • ویرایش: پیام خود را از منوی همان پیام باز و تغییر را ثبت کنید.
  • واکنش: ایموجی انتخاب کنید؛ مدیران کانال می‌توانند مجموعه مجاز را محدود کنند.
  • سنجاق: پیام مهم را در گفتگوی پشتیبانی‌شده سنجاق کنید.
  • ارسال مجدد: مقصد را انتخاب و پیش از تأیید بررسی کنید.
  • حذف: فقط اثر نمایش‌داده‌شده در پنجره تأیید را ملاک قرار دهید.

تصویر

از ابزار تصویر فایل را انتخاب کنید. برنامه آن را برای ارسال آماده می‌کند. با انتخاب تصویر پیام، نمای بزرگ باز می‌شود. اگر بارگیری خودکار تصویر خاموش باشد، روی جایگاه تصویر بزنید تا دانلود شود.

پیام صوتی

دکمه میکروفون را بزنید و مجوز دسترسی مرورگر را بدهید. پس از ضبط، پایان و ارسال را انتخاب کنید. اگر ضبط شروع نمی‌شود، قفل سایت، مجوز microphone، HTTPS و وجود میکروفون را بررسی کنید.

نظرسنجی و ایموجی

دکمه نظرسنجی را باز کنید، پرسش و گزینه‌ها را تکمیل و ارسال کنید. رأی را با انتخاب گزینه ثبت کنید؛ انتخاب چندگانه به تنظیم خود نظرسنجی بستگی دارد. ایموجی را نیز از انتخاب‌گر کنار کادر پیام وارد کنید.

۱۳. استوری‌ها

استوری می‌تواند تصویر، ویدئو یا متن باشد. از دکمه افزودن استوری استفاده کنید، نوع را انتخاب کنید، فایل یا متن و کپشن اختیاری را وارد کنید، مدت نمایش را تعیین و انتشار را تأیید کنید. فایل تصویری یا ویدئویی مجاز انتخاب کنید.

برای دیدن استوری، تصویر کاربر را در نوار استوری‌ها انتخاب کنید. مشاهده می‌تواند به‌عنوان بازدید ثبت شود. برای حذف استوری خود، گزینه حذف را در نمایش استوری انتخاب کنید. محتوای منتشرشده را خصوصی فرض نکنید؛ افراد مجاز ممکن است آن را ذخیره کنند.

۱۴. جستجو و پیام‌های ذخیره‌شده

در کادر جستجوی نوار کناری نام یا شناسه کاربر، گروه یا کانال عمومی را وارد کنید. برای شناسه می‌توانید با یا بدون @ جستجو کنید. گفتگوها را نیز با فیلترهای خصوصی، گروه، کانال و ذخیره‌شده محدود کنید.

پیام‌های ذخیره‌شده فضای شخصی شما برای دسترسی دوباره به پیام یا رسانه است. از منوی پیام گزینه ذخیره/ارسال به پیام‌های ذخیره‌شده را انتخاب کنید یا گفتگوی پیام‌های ذخیره‌شده را باز کنید. سنجاق‌کردن گفتگو آن را در دسترس‌تر می‌کند؛ بایگانی آن را از فهرست اصلی کنار می‌گذارد، اما به معنی حذف نیست.

۱۵. تنظیمات و اعلان‌ها

ظاهر گفتگو

  • تم: روز، شب، OLED یا Arctic.
  • پس‌زمینه: طرح آماده یا تصویر شخصی.
  • اندازه متن: متن پیام را کوچک یا بزرگ می‌کند.
  • گردی حباب: شکل گوشه پیام‌ها را تعیین می‌کند.

اعلان

اجازه اعلان دسکتاپ را از مرورگر درخواست کنید. صدای اعلان را روشن/خاموش یا آزمایش کنید. گزینه پیش‌نمایش متن تعیین می‌کند متن پیام در اعلان دسکتاپ نشان داده شود یا فقط خبر پیام جدید نمایش داده شود. مرورگر ممکن است به‌دلیل تنظیم سیستم‌عامل یا حالت تمرکز اعلان را پنهان کند.

ذخیره‌سازی و رفتار چت

  • پاک‌کردن cache داده‌های موقت مرورگر و Cache Storage را حذف می‌کند.
  • خاموش‌کردن بارگیری خودکار تصاویر باعث می‌شود هر عکس را با کلیک دریافت کنید.
  • بارگیری خودکار صدا فایل‌های صوتی اخیر را برای پخش آماده می‌کند.
  • «ارسال با Enter» کلید ارسال و رفتن به خط بعد را تغییر می‌دهد.
  • «پیمایش خودکار» بعد از پیام جدید صفحه را به انتهای گفتگو می‌برد.

حریم خصوصی

سطح نمایش وضعیت آنلاین و تصویر پروفایل را در گزینه‌های حریم خصوصی تنظیم کنید. گذرواژه حساب را با رمز محلی قفل برنامه اشتباه نگیرید. برای نشست‌های مشترک از حساب خارج شوید.

۱۶. نصب وب‌اپ (PWA)

StarGram را می‌توان در مرورگر سازگار به صفحه اصلی یا فهرست برنامه‌ها افزود. نصب PWA همان سایت و API سرور شما را باز می‌کند و برنامه بومی مستقل یا حالت آفلاین کامل نمی‌سازد.

شرایط نصب

  • سایت عمومی باید با HTTPS باز شود؛ localhost برای توسعه استثناست.
  • مرورگر باید از افزودن سایت به دستگاه پشتیبانی کند.
  • صفحه کامل بارگذاری شود و فایل‌های manifest و service worker در دسترس باشند.

از داخل StarGram

منوی کناری را باز کنید و «نصب اپ» را بزنید. اگر مرورگر پنجره نصب نشان داد، آن را تأیید کنید. بعضی مرورگرها یا سیستم‌عامل‌ها پنجره نصب را در اختیار صفحه نمی‌گذارند؛ در این حالت گزینه نصب را از منوی مرورگر انتخاب کنید.

از منوی مرورگر

  • Chrome/Edge دسکتاپ: منو ← Install app یا Install this site as an app.
  • Android: منوی Chrome ← Install app یا Add to Home screen.
  • iPhone/iPad: Safari ← Share ← Add to Home Screen.

اگر گزینه نصب نیست، HTTPS، سازگاری مرورگر، وضعیت نصب قبلی و service worker سایت را بررسی کنید. اجازه اعلان به معنی نصب PWA نیست. حذف PWA از دستگاه، حساب سرور را حذف نمی‌کند.

۱۷. پنل مدیریت

کاربری که مدیر سامانه است می‌تواند پنل مدیریت را از منوی برنامه باز کند. پنل برای تنظیم و نظارت بر کاربران، گزارش‌ها، گروه‌ها، کانال‌ها و تنظیمات سیستم است. دسترسی عادی نباید اختیار مدیر داشته باشد.

  • مدیریت حساب‌ها و وضعیت کاربران؛
  • رسیدگی به گزارش‌ها و مدیریت گفتگوهای گروهی/کانالی؛
  • تنظیمات سامانه و اتصال اختیاری Gemini؛
  • خروجی و بازیابی پشتیبان JSON در حالت محلی.

کلید API Gemini را فقط در پنل/تنظیم امن سرور وارد کنید؛ هرگز آن را در فایل‌های فرانت‌اند یا مخزن عمومی قرار ندهید. درخواست دستیار فقط وقتی ارسال می‌شود که قابلیت فعال و استفاده شود.

۱۸. مدیریت سرور با فرمان stargram

نصب‌کننده لینوکس فرمان مدیریت را ایجاد می‌کند. بسته به کاربر و دسترسی سرویس، آن را با sudo اجرا کنید:

sudo stargram                 # Open the management menu
sudo stargram status          # Service and database status
sudo stargram start
sudo stargram stop
sudo stargram restart
sudo stargram logs             # Recent logs
sudo stargram logs follow      # Follow logs live
sudo stargram health           # Check the health endpoint
sudo stargram port 8080        # Change the HTTP port
sudo stargram backup           # Create a backup
sudo stargram admin            # Reset administrator credentials
sudo stargram update           # Update application code
sudo stargram help

منوی تعاملی، promptها و خروجی ترمینال به انگلیسی هستند. زیر‌فرمان port پیکربندی پورت را تغییر می‌دهد؛ پس از تغییر، reverse proxy و firewall را نیز هماهنگ کنید. دستور uninstall را فقط پس از backup و بررسی داده‌ها اجرا کنید.

۱۹. به‌روزرسانی

برای نصب‌های ایجادشده با اسکریپت، از این فرمان استفاده کنید:

sudo stargram update

به‌روزرسانی نسخه شاخه main را مستقیم از GitHub دریافت می‌کند؛ بنابراین پوشه نصب لازم نیست Git repository باشد و خطای fatal: not a git repository از اجرای pull در پوشه غیر Git پیش نمی‌آید. فرمان از داده‌ها backup می‌گیرد، فایل‌های برنامه را تازه می‌کند، وابستگی‌ها را نصب و build را اجرا می‌کند، schema را آماده می‌کند و در صورت وجود systemd سرویس را restart می‌کند.

مواردی که حفظ می‌شوند: data/، backups/، فایل‌های .env و node_modules/. تغییرات محلی کد ممکن است بازنویسی شوند. قبل از آپدیت، پشتیبان مستقل بگیرید و سفارشی‌سازی کد را ثبت کنید.

اگر نصب را دستی انجام داده‌اید و مسیر Git checkout است، روش به‌روزرسانی شما می‌تواند متفاوت باشد؛ از فرمان مدیریت همین نصب یا روش نگهداری خودتان استفاده کنید و هم‌زمان دو روش را روی یک سرور اجرا نکنید.

۲۰. پشتیبان‌گیری و بازیابی

در حالت JSON، داده اصلی در data/stargram_db.json است. فرمان sudo stargram backup نسخه فشرده می‌سازد. در SQL، فرمان از ابزار dump موتور پایگاه داده استفاده می‌کند؛ utilityهای متناظر باید روی سرور نصب و اتصال دسترسی‌پذیر باشد.

پنل مدیریت نیز برای حالت محلی امکانات خروجی و بازیابی JSON دارد. بازیابی را ابتدا روی نسخه آزمایشی یا پس از گرفتن backup از داده فعلی انجام دهید؛ فایل نامتناسب یا قدیمی ممکن است داده تازه‌تر را جایگزین کند.

  • فایل‌های backup را از document root وب دور نگه دارید.
  • پشتیبان را روی همان دیسکی که داده اصلی است تنها نسخه نگه ندارید.
  • برای SQL، علاوه بر برنامه StarGram، پایگاه داده را در برنامه backup دوره‌ای وارد کنید.
  • دوره‌ای مطمئن شوید backup قابل خواندن و بازیابی است.

۲۱. امنیت و حریم خصوصی

  • از رمز قوی و متفاوت برای حساب مدیر و حساب پایگاه داده استفاده کنید.
  • برای دامنه عمومی HTTPS را اجباری کنید و دسترسی مستقیم به فایل‌های سرور را ببندید.
  • مقادیر .env، رمزها و کلید Gemini را در مخزن GitHub قرار ندهید.
  • پوشه‌های داده و backup را فقط برای کاربر/سرویس لازم قابل خواندن کنید.
  • محدودیت دسترسی پنل مدیر را رعایت و نرم‌افزار سیستم‌عامل را به‌روز نگه دارید.
پیام‌های StarGram در قالب فعلی رمزگذاری سرتاسری (E2EE) نشده‌اند؛ متن قابل‌خواندن در داده همگام‌شده ذخیره می‌شود. این سرویس را معادل پیام‌رسان با E2EE فرض نکنید.

رمز عبور حساب با scrypt هش می‌شود و token نشست به شکل هش در سرور نگهداری می‌شود؛ با این حال، این پروژه را بدون ارزیابی مستقل امنیتی تلقی کنید. استفاده از Gemini اختیاری است و محتوایی که برای دستیار می‌فرستید به ارائه‌دهنده یا proxy پیکربندی‌شده ارسال می‌شود.

۲۲. رفع اشکال

npm run build خطای TypeScript می‌دهد

از پوشه اصلی پروژه اجرا کنید. مطمئن شوید checkout کامل است و فایل‌ها روی لینوکس با حروف بزرگ/کوچک درست قرار دارند. روی نسخه سرور git status و حضور فایل‌های مورد اشاره در خطا را بررسی کنید؛ سپس از شاخه معتبر پروژه npm ci و npm run build را اجرا کنید.

fatal: not a git repository هنگام آپدیت

نسخه فعلی فرمان sudo stargram update لازم نیست پوشه نصب Git repository باشد و آرشیو شاخه main را مستقیم دریافت می‌کند. اطمینان حاصل کنید که فرمان نصب‌شده در /usr/local/bin/stargram از همان نسخه جدید است؛ در صورت خطا log را با sudo stargram logs ببینید.

سایت باز نمی‌شود یا سرویس خاموش است
sudo stargram status
sudo stargram logs
sudo stargram health
sudo ss -ltnp

پورت تنظیم‌شده در .env، firewall، reverse proxy و وضعیت systemd را بررسی کنید. اگر systemd موجود نیست، از پوشه پروژه npm start را با مدیر فرایند اجرا کنید.

صفحه باز می‌شود اما ورود یا پیام‌رسانی کار نمی‌کند

بخش /api را در proxy بررسی کنید، مطمئن شوید proxy درخواست‌ها و WebSocketهای لازم را به پورت StarGram می‌فرستد و سرور از مرورگر قابل دسترسی است. Console مرورگر و log سرور را هم بررسی کنید.

برنامه به‌جای SQL از JSON استفاده می‌کند

DB_TYPE، میزبان، پورت، نام دیتابیس، کاربر و سطح دسترسی را در .env بررسی کنید. وضعیت موتور را از sudo stargram status یا پنل مدیریت بخوانید. پاسخ HTTP سالم به‌تنهایی سلامت اتصال SQL را ثابت نمی‌کند.

آپلود عکس/صدا یا ضبط میکروفون ناموفق است

HTTPS، اندازه مجاز درخواست در Nginx/Caddy، فضای دیسک، مجوز میکروفون مرورگر و دسترسی کاربر سرویس به فایل‌ها را بررسی کنید. پس از تغییر محدودیت proxy، سرویس را reload کنید.

دکمه نصب PWA نمایش داده نمی‌شود

HTTPS، مرورگر پشتیبانی‌شده، نصب‌نشدن قبلی سایت، بارگذاری manifest/service worker و گزینه Add to Home Screen در منوی خود مرورگر را بررسی کنید. اعلان مرورگر به‌تنهایی باعث نصب PWA نمی‌شود.

اعلان مرورگر یا صدا نمی‌آید

مجوز اعلان سایت و سیستم‌عامل، وضعیت mute گفتگو، گزینه صدای اعلان، فعال‌بودن تب/مرورگر و تنظیمات Do Not Disturb را بررسی کنید. بعضی مرورگرها تا تعامل کاربر اجازه پخش صدا نمی‌دهند.

۲۳. پرسش‌های رایج

آیا GitHub Pages خود پیام‌رسان را اجرا می‌کند؟

خیر. Pages این سایت معرفی و مستندات را میزبانی می‌کند. برنامه نیازمند Node.js و API روی سرور شماست.

آیا برای استفاده پایگاه داده SQL اجباری است؟

خیر، حالت JSON محلی برای نصب ساده وجود دارد. PostgreSQL و MySQL/MariaDB هم پشتیبانی می‌شوند.

آیا برنامه رایگان و متن‌باز است؟

کد با مجوز MIT منتشر شده است. هزینه VPS، دامنه و سرویس‌های جانبی را میزبان/مدیر سرور پرداخت می‌کند.

آیا اپ Android یا iOS جداگانه وجود دارد؟

نسخه این مخزن وب است و می‌تواند به صورت PWA به صفحه اصلی افزوده شود؛ اپ بومی جداگانه در این مخزن ارائه نشده است.

برای درخواست قابلیت یا گزارش خطا کجا بروم؟

نسخه، سیستم‌عامل، مراحل بازتولید و متن کامل خطا را بدون رمز، token یا داده خصوصی در GitHub Issues ثبت کنید.

برای بررسی کد، تاریخچه و انتشارهای پروژه به مخزن StarGram در GitHub بروید.
